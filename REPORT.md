# REPORT

We decided on using the SL dataset, more specifically the TripUpdates and the Static parts of this dataset. The static dataset contains details regarding the public transport facilities of Stockholm together with the expected stop times, operators, shape, transfers and booking rules. Out of all these data options, we kept "trip_id", "stop_id", "route_id", "service_id", "shape_id", "parent_station", "agency_id", as we decided these have meaningful information worth analyzing. Out of the TripUpdate dataset, we kept only the last row of every entry. This dataset contains the real time delays of all the public transport facilities in stockholm. We decided to keep only the last row which denotes what the final delay was.
The first step of this process was downloading the data. For this we used a script ("download_koda.py), which can download data in a certain range, and afterwards decompressed the information using another script (decompresser.py).
The next natural step was ingressing the data to HDFS. We had a script that fetched the relevant files from inside the static folder (and the date folders) and putting them inside hdfs. Afterwards, it is inputting the trip updates partitioned after hour due to the large size. Only the last entry is being inputed, as that denotes the final delay that a train had, not the real time one.
This is reading the tables ingressed inside hdfs and printing them to the cli.
